# Nova-mk-feature-dossiers

**Inputs:** Mk context from mk_prepare (domains, features, updates, **affected_features**); handoff (user request, implement summary; **compressed_context** when provided by mk_gather_context). Spec index and registries for path resolution and full spec when compressed context is absent or incomplete.

**Outputs:** For each feature in scope: the resolved summary file under `<docs_dir>/features/domain/...` (or an intentional `doc_path` override) and seven sub-files (how-it-works.md, change-log.md, known-issues.md, decisions.md, contracts.md, tests.md, diagrams.md). Pass/Fail and count of dossiers updated.

## Instructions

1. Read **@.cursor/skills/nova-code/mk/page-formats.md** for every feature file type (feature summary and the seven sub-pages). Follow the exact section order and headings.
2. **Scope:** When mk context includes **affected_features** (a list of domain/feature pairs), iterate over **affected_features** only. When **affected_features** is absent or denotes "all," iterate over the full features list from prepare.
3. **Compressed context:** When handoff includes **compressed_context** (markdown bundle from mk_gather_context), use it as the **primary source** for requirement statements, acceptance criteria, assets (path, role), and validation tests when filling the feature summary and sub-pages (how-it-works, contracts, tests). Only open the full registry (and existing mkdoc files) when a section or field is missing from the compressed context or for path resolution. If compressed_context is absent, read from the full registry and existing docs as today.
4. **Path resolution:** When building the path to the feature summary and sub-pages, prefer **feature.doc_path** from the registry when present: summary file = &lt;docs_dir&gt;/&lt;feature.doc_path&gt;, sub-pages directory = &lt;docs_dir&gt;/&lt;dirname(feature.doc_path)&gt;/&lt;feature.slug&gt;/ (e.g. how-it-works.md in that directory). If **doc_path** is absent, derive from the effective domain slug: summary = `&lt;docs_dir&gt;/features/domain/&lt;domain&gt;/&lt;feature-name&gt;.md`, sub-pages = `&lt;docs_dir&gt;/features/domain/&lt;domain&gt;/&lt;feature-name&gt;/`. Load feature from the registry for the feature's domain when doc_path is needed.
5. For **each feature** in scope, create the sub-pages directory if needed. Then:
   - **Feature summary** — File: path from step 4 (summary path). Content: H1 feature display name, # Status (draft/active/deprecated; if deprecated link successor), # Summary, # Key assets (from compressed_context or spec assets), # Sub-pages (bulleted links to the seven sub-pages). Create if new feature; update if behavior change, refactor, or deprecation. Write or overwrite.
   - **how-it-works.md** — File: sibling feature directory + `how-it-works.md`. Content: # How it works, # Overview, # Flow, # Inputs and outputs. **Must** be filled from compressed_context (when present) or the current registry spec (behavior/requirements); do not invent content that is not in the spec. Write or overwrite.
   - **change-log.md** — File: sibling feature directory + `change-log.md`. Content: # Change log, # Entries (## YYYY-MM-DD). If handoff says "behavior change" or "any change," append or merge a new entry with today's date and short description. Preserve prior entries unless an existing entry matches the same stable identity. Do not replace the whole history file unless bootstrapping from empty.
   - **known-issues.md** — File: sibling feature directory + `known-issues.md`. Content: # Known issues, # Active, # Resolved. If handoff says "bug/root cause," add or update an issue entry by stable issue key or normalized title; move entries between Active and Resolved instead of discarding history.
   - **decisions.md** — File: sibling feature directory + `decisions.md`. Content: # Decisions, # Entries (## YYYY-MM-DD — title). If handoff says "behavior change," add or update a decision note keyed by date + title. Preserve prior decisions by default.
   - **contracts.md** — File: sibling feature directory + `contracts.md`. Content: # Contracts, # APIs, # Schemas, # Interfaces. **Must** be filled from compressed_context (when present) or the current registry spec; do not invent content that is not in the spec. Write or overwrite.
   - **tests.md** — File: sibling feature directory + `tests.md`. Content: # Tests, # Coverage, # Test list (from compressed_context when present or spec validation.tests). **Must** be filled from the current registry spec (validation.tests) when compressed_context lacks it. Write or overwrite.
   - **diagrams.md** — File: sibling feature directory + `diagrams.md`. Content: # Diagrams, # Architecture (link or Mermaid), # Feature flow. When linking to the main architecture page, use `../../../../architecture.md`. Write or overwrite.
6. Use relative links (e.g. from feature summary to `how-it-works.md`, `change-log.md`, etc.). Apply maintenance rules: new feature → create full dossier; behavior change → update summary + decisions; schema change → contracts; deprecation → set status and link successor. **Key assets, contracts, tests, and how-it-works must be filled from compressed_context when present, else from the current registry spec; do not invent content that is not in the spec.**
7. Return: Pass (or Fail), and one line e.g. "Updated 3 feature dossiers (24 files)."
