# Nova-spec output format

**Purpose:** Single source of truth for the structure of the nova-spec run report. Used so every run returns a consistent, comparable report.

**Inputs:** Result of scan-and-update (outcome, summary, phases, changed spec paths, changed mkdoc paths, domains).

**Output:** A final report that follows the section order below. **Report title / project name:** Use project name from **@.cursor/project.yml** `project_name` or first registry `project.name` when filling the report header (e.g. "Nova-spec run report — &lt;project name&gt;").

---

## Report structure (required order)

Produce the report in this order. If the run failed partway, still include all sections; use **Fail** for Outcome and note the reason and any partial results in Summary and Issues/notes.

### 1. Outcome

One line: **Pass** or **Fail**. If Fail, include a one-line reason (e.g. "Fail. Reason: consistency check failed; orphan requirement REQ-X in registry.").

### 2. Summary

Short prose summary of what was done. Examples:

- "Updated specs and mkdoc: added N requirements, M assets; synced mkdoc from features."
- "No semantic changes; registries and docs were already in sync, so schema.updated_utc was left unchanged."
- "Updated specs: added domain X; wrote X-registry.yml. Mkdoc synced; N feature dossiers updated."

### 3. Phases executed

List the scan-and-update phases with status per phase: **Pass** | **Fail** | **Skipped**.

| Phase  | Status |
|--------|--------|
| Scan   | Pass / Fail / Skipped |
| Update | Pass / Fail / Skipped |
| Write  | Pass / Fail / Skipped |
| Mkdoc  | Pass / Fail / Skipped |

Enables quick validation that all phases ran. If a phase was skipped, note why in Issues/notes if relevant.

### 4. Specs updated

Bulleted list or table of changed **spec** file paths (e.g. `specs/specs.yml`, `specs/core-registry.yml`, `specs/connectors-registry.yml`). If none: "None."

### 5. Mkdoc updated

Bulleted list or table of changed **docs-dir** paths (e.g. `mkdoc/index.md`, `mkdoc/features/domain/core.md`, `mkdocs.yml`). Use the configured docs root from project config. If none: "None."

### 6. Domains

Short line listing which domains were considered (e.g. "Domains: core, connectors."). Optional but useful for traceability.

### 7. Issues / notes

- If **Fail:** Reason and any partial results (e.g. which phase failed, what was written before failure).
- If **Pass:** Optional line (e.g. "Consistency check passed; no schema violations.").

---

## Footer

Close with a one-line footer:

*Report generated by nova-spec. Workflow: nova-spec.*
