# Cursor-backed gathering workflow

# Status

active

# Summary

Luna bot gathering workflow and Cursor Cloud execution (REQ-LUNA-001). The shipped `luna` bot stays config-driven in `config/bots.yaml`, activates from `discordMention: luna` (and optional `discordAuthors`), runs configured workflow `luna_cursor` to gather repository and feature inputs across multiple Discord turns, then uses the **full provisioning sequence** for launch. **Guided repo selection:** the first step uses `choiceProvider: githubRepos` to present GitHub repos (from GitHub API, sort=updated), "Use last repo", and "Custom repo"; last repo is stored per author after a successful launch. A **confirmation step** (Launch / Edit repo / Edit request / Cancel) runs before the provisioning sequence. **After Launch**, the flow may include **provision_room_participants** (storeIn: featureRoomParticipants) and **initialize_feature_room_state** before or after channel/thread creation for multi-bot feature rooms; **initialize_feature_plan_state** and **ensure_repo_workspace** run after room state init in `luna_cursor` (plan aggregate + repo workspace linkage). **`upsert_artifact_section_data`** and **`get_profile_missing_fields`** follow **ensure_repo_workspace** in `luna_cursor` to populate **`FeaturePlanState.artifacts`** and **`profileMissingSummary`** (plain-English summaries). Luna then **`post_channel_message`**s a handoff into the intake thread, **`start_coordinator_planning`** runs the coordinator workflow once in that thread (synthetic in-process Discord message; same session key as later user replies), and **`done`**s in the main channel. The production coordinator path is now **`arrietty_room_v2`**: a draft-first intake that hydrates plan/session state, ensures repo workspace linkage, runs autonomous planning passes, posts the planning packet, critiques it, and routes Phase C by canonical decision projections only. The planning review checkpoint is distinct from the approval checkpoint, and approval stays gated on canonical plan approval state before **`launch_cursor_run`**. Arrietty uses **`conversationMode: conversational`** so thread-scoped workflows return a stable idle reply after terminal **done** instead of restarting. The Luna provisioning sequence still runs: `create_channel` (builds **CreateRoomRequest** via request factory; resolves **SpaceOperations** via **WorkflowCapabilitySupport.sourcePrefix(event)** — fail-closed) → branch on `channelId == CHANNEL_CREATE_FAILED` → `provision_bot_instance` → `create_lifecycle_context` → `create_thread` (**CreateThreadRequest**; **DiscordSpaceOperations** uses request getters only) → room/plan/repo steps → thread handoff. **`launch_cursor_run` is the authoritative launch path** for the feature (thread workflow); `cursor.fullRun` is not used in `luna_cursor`. The Cursor run prompt is built by **`CursorInstructionComposer`** (single source; includes /nova-code). `LifecycleContext` is extended with `configuredBotId`, `runtimeBotInstanceId`, and optional `repo`/`requestText`. Vinekeepers stores `LifecycleRunRecord` and `luna:lastRepo:{authorId}`, polls Cursor, and relays launch/progress/PR updates back to Discord. The **Arrietty** bot is the template for per-channel lifecycle room instances; `RuntimeBotInstance` uses a generic instance id. In the Luna provisioning sequence, **create_thread** runs **after create_lifecycle_context**; CreateThreadAction uses the **lifecycle owner gateway** when the channel has a context and updates **LifecycleContextStore** via **setDeliveryTargetId**(contextId, threadId); **LifecycleContext.withDeliveryChannelId** supplies the delivery target for the store. Arrietty can use a **create_thread** step (bind `channelId`, `threadName`; `storeIn: deliveryChannelId`) so Cursor updates are delivered to the thread. The **done step** may use a short **main-room redirect** message (e.g. `"Launching now. See <#{{channelId}}>."`). `LifecycleRunRecord` and `CreateLifecycleContextAction` support optional **deliveryChannelId** (excludes `THREAD_CREATE_FAILED`); **PostChannelMessageAction** send target is `deliveryChannelId` or `channelId` (bind then state); **CursorCloudRunMonitor** sends status/feedback to the thread when `deliveryChannelId` is set (messageId null).
